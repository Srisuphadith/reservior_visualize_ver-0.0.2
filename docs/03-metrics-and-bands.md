# 03 · ตัวชี้วัด ระดับสถานะ และสี

## ตัวชี้วัดรายอ่าง

คำนวณใน `normalizeReservoir()` (`backend/src/normalize.ts`)

| ฟิลด์ | สูตร | เมื่อไหร่เป็น null |
|---|---|---|
| `percent` | ใช้ `percent_storage` จาก RID ถ้า RID ไม่ส่งมาก็คำนวณเองจาก `volume / storage × 100` | `volume` เป็น null หรือ `storage` = 0 |
| `usable` (น้ำใช้การได้) | `max(volume − dead_storage, 0)` | `volume` เป็น null |
| `netFlow` | `inflow − outflow` | `inflow` หรือ `outflow` เป็น null |
| `band` | `bandOf(percent)` | ไม่เคยเป็น null ถ้าไม่มีข้อมูลจะเป็น `"nodata"` |

## ตัวชี้วัดระดับกลุ่ม (ทั้งประเทศ / รายภาค)

คำนวณใน `summarize()` (`backend/src/metrics.ts`)

| ฟิลด์ | ความหมาย |
|---|---|
| `count` | จำนวนอ่างทั้งหมดในกลุ่ม |
| `reporting` | จำนวนอ่างที่วันนี้มีค่า `volume` |
| `storage` | ผลรวมความจุของ**ทุกอ่าง** |
| `reportingStorage` | ผลรวมความจุของ**อ่างที่รายงานข้อมูล**เท่านั้น |
| `volume` | ผลรวมปริมาณน้ำ ไม่นับอ่างที่ไม่มีข้อมูล |
| `usable` | ผลรวมน้ำใช้การได้ |
| `percent` | `Σ volume / Σ reportingStorage × 100` |
| `bands` | จำนวนอ่างในแต่ละระดับสถานะ (6 ระดับ รวม nodata) |

### ทำไมไม่เฉลี่ย % ของแต่ละอ่าง

สมมติมีอ่างเล็ก 1 ล้าน ลบ.ม. ที่เต็ม 100% และอ่างใหญ่ 99 ล้าน ลบ.ม. ที่มีน้ำ 10%

- **เฉลี่ย %:** (100 + 10) / 2 = **55%** ❌ อ่างเล็กมีน้ำหนักเท่าอ่างใหญ่
- **คิดจากผลรวม:** (1 + 9.9) / (1 + 99) = **10.9%** ✅ ตรงกับปริมาณน้ำจริง

มี test นี้อยู่ใน `backend/test/metrics.test.ts` ชื่อ "percent uses sums, not the average of percentages"

### ทำไมตัวหารเป็น `reportingStorage` ไม่ใช่ `storage`

ถ้าเอาความจุของอ่างที่ไม่มีข้อมูลมาเป็นตัวหาร % จะต่ำกว่าความจริง เพราะเท่ากับนับอ่างพวกนั้นเป็นอ่างว่าง
ระบบจึงส่งทั้งสองค่าออกไป และ KPI จะแสดงว่า "จากความจุ X ล้าน ลบ.ม." ให้ผู้ใช้รู้ว่า % นี้คิดจากฐานไหน

ตัวเลขทั้งประเทศวันที่ 2026-10-03: `count` 461, `reporting` 455, `volume` 4,657.86, `reportingStorage` 5,808.08 ได้ **80.2%**

### การปัดเศษ

backend ปัดปริมาณน้ำเป็นทศนิยม 3 ตำแหน่งและ % เป็น 2 ตำแหน่ง ส่วน frontend แสดงปริมาณน้ำ 2 ตำแหน่งและ % 1 ตำแหน่ง

## ระดับสถานะน้ำ

กำหนดใน `backend/src/bands.ts` ตัวเลขแต่ละตัวเป็น**ขอบบนแบบรวมค่านั้นด้วย**

| band | ช่วง | ป้าย | ไอคอน |
|---|---|---|---|
| `critical` | ≤ 30% | น้ำน้อยวิกฤต | ▼▼ |
| `low` | > 30 – 50% | น้ำน้อย | ▼ |
| `normal` | > 50 – 80% | น้ำปกติ | ● |
| `high` | > 80 – 100% | น้ำมาก | ▲ |
| `over` | > 100% | เกินความจุ | ▲▲ |
| `nodata` | volume เป็น null | ไม่มีข้อมูล | – |

ตัวอย่าง: 30.00 → critical, 30.01 → low, 100 → high, 100.01 → over (มี test ครอบทุกขอบ)

> ⚠️ เกณฑ์เหล่านี้**เป็นค่าที่โปรเจกต์เสนอเอง ไม่ใช่มาตรฐานของกรมชลประทาน** ถ้าจะเปลี่ยน ให้แก้ 3 ที่ให้ตรงกัน:
> 1. `backend/src/bands.ts` ที่เก็บเกณฑ์ตัวเลข
> 2. `frontend/src/config/bands.ts` ที่เก็บข้อความช่วง (`range`) ที่แสดงบน UI
> 3. test ใน `backend/test/bands.test.ts`

## สี

### หลักการ

ระดับสถานะเป็นข้อมูลแบบ**มีลำดับและมีจุดกึ่งกลาง** (น้อย → ปกติ → มาก) จึงใช้ **diverging palette**:
แดง (น้ำน้อย) → เทา (ปกติ) → น้ำเงิน (น้ำมาก)

| band | Light | Dark |
|---|---|---|
| critical | `#b42e2e` | `#d03b3b` |
| low | `#ec835a` | `#f0a080` |
| normal | `#cfcec6` | `#6b6a64` |
| high | `#5598e7` | `#3987e5` |
| over | `#1c5cab` | `#9ec5f4` |

- ชุดสีผ่านการตรวจระยะห่างของสีสำหรับคนตาบอดสี (CVD ΔE ≥ 8) และสำหรับคนตาปกติ (ΔE ≥ 15) ทั้งบนพื้นสว่างและพื้นมืด
- **สถานะไม่เคยแสดงด้วยสีอย่างเดียว** มีป้ายข้อความและไอคอนกำกับเสมอ ทั้งใน badge, legend และ tooltip
- กราฟเปรียบเทียบรายภาคใช้สีน้ำเงินสีเดียวทุกแท่ง ไม่ได้ลงสีตามค่า เพราะความยาวแท่งบอกค่าอยู่แล้ว
- `nodata` ไม่อยู่ในกราฟแท่งซ้อน แต่แสดงเป็นข้อความ "ไม่รวมอ่างที่ไม่มีข้อมูล N อ่าง" แทน

### ทำไมสีอยู่ใน TypeScript ด้วย ไม่ใช่แค่ CSS

Recharts ใส่สีเป็น attribute ของ SVG (`fill="..."`) ซึ่งใช้ CSS variable ไม่ได้ จึงต้องเก็บสีไว้ใน `frontend/src/config/bands.ts`
แล้วเลือกชุดสีตามโหมดผ่าน hook `useColorScheme()` ส่วน badge ที่เป็น HTML ใช้ CSS variable `--band-*` ใน `styles.css`
**ถ้าเปลี่ยนสี ต้องแก้ทั้งสองไฟล์ให้ตรงกัน**
